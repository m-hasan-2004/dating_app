# Fix Swagger UI for Cookie-Based JWT Auth

## Problem
Swagger UI's Authorize button exposes a Bearer token input (`jwtAuth` scheme) — the user wants this removed since auth uses HTTP-only cookies. After calling login, the Authorize button doesn't change state.

## Root Cause
- `jwtAuth` (Bearer header) scheme in `settings.py:352-358` adds a token input to Swagger's Authorize dialog
- Swagger UI can't natively handle HTTP-only cookie auth — it can't read/set these cookies from JS
- The `jwtCookieAuth` apiKey-in-cookie scheme also doesn't work properly with Swagger UI

## Changes

### 1. Remove Bearer scheme from OpenAPI spec
**`backend/dating_app/settings.py`**
- Remove `jwtAuth` from `SECURITY_SCHEMES` dict (lines 353-358)
- Remove `{"jwtAuth": []}` from `SECURITY` list (line 351)  
- Update `DESCRIPTION` to remove "In Swagger UI you can still use the Authorize button with a Bearer..." text

### 2. Create custom Swagger UI template with login form
**New file: `backend/templates/custom_swagger_ui.html`**
- Base on drf-spectacular's default template structure
- Add a top bar with: username input, password input, Login button, Logout button, auth status
- Login button: `POST /api/auth/login/` with credentials → server responds with `Set-Cookie` → browser auto-stores HTTP-only cookie
- Logout button: `POST /api/auth/logout/` → clears cookies
- After login, all Swagger API requests auto-include the cookie (same-origin)
- Style the bar to sit above the Swagger UI, not block it

### 3. Wire up the custom template
**`backend/dating_app/urls.py`**
- Subclass `SpectacularSwaggerView` setting `template_name = "custom_swagger_ui.html"`
- Or pass it directly: `SpectacularSwaggerView.as_view(url_name="schema", template_name="custom_swagger_ui.html")`

**`backend/dating_app/settings.py`**
- Add `BASE_DIR / "templates"` to `TEMPLATES["DIRS"]` so Django finds the custom template

### 4. No changes needed to auth backend
- `LoginView` already has `permission_classes = [AllowAny]`
- `CookieJWTAuthentication` already works — browser sends HTTP-only cookie automatically on same-origin requests

4. Logout → GET `/api/auth/me/` → 401
5. `python manage.py test users.tests.test_cookie_auth` — all existing tests pass
